# ScreenDesk

代码仓库：[Yankersey/SHHConnector](https://github.com/Yankersey/SHHConnector)。[Windows / WSL 安装](WINDOWS.md) · [修改与双机同步](CONTRIBUTING.md)。

本地 SSH / GNU screen 工作台，支持 macOS / Linux / 原生 Windows，Python 3.9+。macOS / Linux 无需 pip、npm 安装；Windows 仅需 pywinpty，终端网页资源均已打包。

## 启动

macOS 解压整个文件夹后，双击 **启动 ScreenDesk.command**。浏览器会自动打开。也可在程序目录运行：

```sh
sh start.sh
```

macOS 12.3 或更新版本也可在项目目录运行 `sh install-macos-app.sh`，再从 Finder 的个人「应用程序」文件夹打开 **ScreenDesk.app**。它有独立的窗口和程序坞图标。安装器使用 Apple 命令行工具编译，按提示运行 `xcode-select --install` 即可安装工具。如果 macOS 询问是否允许访问项目所在的「文稿」文件夹，选择允许。

关闭应用窗口时后台继续运行，点击程序坞图标可重新打开工作台。使用 ⌘Q 退出时，应用自己启动的后台会分离终端并退出。如果打开应用前已经有后台在运行，应用会复用它，可用工作台里的「退出程序」关闭该后台。下次打开时会检查 Git 更新。

Linux 运行 `sh start.sh`。Windows 首次双击 **setup-windows.cmd**，再双击 **install-windows-shortcuts.cmd**，以后从桌面或开始菜单打开 **ScreenDesk**。原生版直接使用 Windows Python、ConPTY 和系统 OpenSSH，无需 WSL 或虚拟机。详见 [Windows 使用说明](WINDOWS.md)。WSL 方式见 [start-wsl.cmd](WINDOWS-WSL.md)。服务器需要 SSH、SFTP 和 GNU screen，不需要远程 Python。

Git 克隆版本会在启动器启动前检查远程分支并执行快进更新；界面左下角显示提交号。离线 / 开发时显式使用 `sh start.sh --offline`。直接运行 `python3 app.py` 可以启动本地代码，但不会检查 Git 更新。ZIP 版本不包含 .git，因此没有自动更新功能。

两台电脑应分别克隆同一个仓库；修改后提交并推送，另一台退出旧程序并重新启动即可拉取。SSH 配置、密钥、布局、断点与下载数据均保留在各自电脑，不上传仓库。

再次双击启动器会打开已有程序。退出请点右上角“退出程序”，或在启动的终端按 Ctrl+C。

## 服务器与工作区

- 左侧直接读取 **~/.ssh/config** 的具体 Host 别名，支持 Include。点击 ↻ 重新读取，不需要手工录入服务器。
- `Host *`、带通配符和否定的规则不单独列为机器；连接时仍由系统 SSH 完整解析配置，包括端口、用户名、私钥、跳板机及匹配规则。
- 点击服务器会切换**整个终端工作区**。其他服务器的 SSH、终端和下载继续保持，切换本身不分离会话。
- 点顶部左侧的菜单按钮可收起或展开侧栏。桌面浏览器会记住这个选择。
- 顶部仅保留连接信息和操作按钮，让终端获得更多空间。
- 如需使用其他 config：`python3 app.py --ssh-config /你的路径/config`。

Include 只静态读取 Host 别名，不执行 Match exec。放在复杂条件 Include 里的别名可能也会显示；最终连接行为以系统 SSH 对该别名的解析为准。

## 新建与恢复终端

1. 选择服务器，点“新建窗口”。**必须命名**，支持中文。
2. 每个新窗口都要明确选择是否启用 SSH 配置中的端口转发；不同窗口可以选择不同方式。
3. 终端连接中的密码、密钥口令、二次认证和首次指纹确认，仍在终端内按系统 SSH 提示处理；扫描、文件操作和会话管理需要认证时，会弹出“SSH 身份认证”对话框。
4. 每个窗口对应一个独立 GNU screen，可运行 bash、Python、vim、htop 等终端程序。

拖动标题栏移动，拖动八个方向的边缘 / 角落调整大小；双击标题栏或点 □ 最大化 / 还原。A− / A＋ 调字号。平铺、层叠仅整理当前服务器的窗口。布局自动保存。

新建 screen 直接使用统一命名规则：`sd2_<窗口名称>_<12位唯一后缀>`，例如 `sd2_模型训练_a1b2c3d4e5f6`。中文、字母、数字、点、横线和下划线直接保留；空格等字符按 UTF-8 字节转为 `~HH`，扫描时无损还原。名称完整保存在 screen 自身，不额外创建服务器映射文件。为避免 socket 名称过长，完整 screen 名称最多 64 字节；过长时会提示缩短，不截断名称。

新建对话框中可填写已有 `PID.name`，接管已有 screen（会分离它原有的终端）。

## 扫描与双机添加

选择服务器后点 **扫描服务器 screen**，读取当前 SSH 账号的 `screen -ls`。显示附加 / 分离 / 失效状态，并按上述规则识别窗口名称；不符合规则的普通或旧版 screen 仍按原始名称列出，不会擅自重命名。

- **添加到本机**：只添加本机记录并恢复窗口，默认不连接。已在本机的会话不能重复添加；失效 socket 不允许添加。
- **忽略 / 取消忽略**：只保存在当前电脑；勾选“显示已忽略”可恢复。忽略扫描结果不会移除已经添加的本机会话。
- 在另一台 Windows 或 Mac 上使用同一服务器的同一 SSH 账号，扫描并选择添加，即可得到服务器中相同的窗口名称。不通过 Git 同步 SSH 配置、密钥或布局。
- 添加后，点“重新连接”才附加。两台电脑各自运行 ScreenDesk 时，如果同一个 screen 已在另一台电脑连接，请先在原端分离，再在当前电脑连接。
- 扫描是只读操作，不执行 `screen -wipe`、删除 socket、分离或结束任何会话。网络错误、权限问题或超时不删除已有记录。没有公钥时，可以直接在界面的 SSH 认证对话框中输入密码 / 验证码。

## 密码、私钥口令与验证码

扫描 screen、读取文件列表、下载、核对 / 诊断 / 结束会话均沿用系统 OpenSSH。可用的密钥、agent 或已认证的复用连接照常使用；需要密码、加密私钥口令或 MFA 时，界面会显示服务器、当前操作及 SSH 原始提示，按提示输入即可，不需要先打开一个终端。

- 输入只交给当前 SSH 进程的 askpass 管道，不写入磁盘、布局、下载记录、命令行参数或日志，不缓存后代填。新的独立连接可能再次要求认证；Windows 和 macOS 都支持。
- 首次主机指纹确认需要明确点击“确认并继续”；对话框显示 SSH 的连接信息 / 指纹。主机密钥变更仍由系统 SSH 拒绝，不自动接受或关闭指纹检查。
- 等待用户输入的时间不计入原来的 SSH 操作 / SFTP 通信超时。每条认证提示最多等待 3 分钟。
- 取消认证或认证失败时，扫描 / 读取文件返回错误并保留已有记录；下载暂停并保留断点，点“继续”可重新认证。不会无限重复弹出密码框。
- SSH 配置、跳板机、反代和端口转发规则不改变。普通终端及 Windows 共享转发连接的交互登录仍在终端内完成。

## 关闭与保留

- **核对会话**：只核对当前服务器在本机记录的 screen。确认远程已不存在时，移出工作区并停止该窗口的连接；SSH 掉线、超时、权限问题和坏 socket 都显示“无法确认”，保留记录。
- 左侧每条会话都有 **删除本机记录**，窗口 × 中也可选 **仅删除本机记录**，核对窗口仍提供本机记录移除。服务器无响应、screen 卡住或创建失败时也可立即删除：先保存本机删除结果，再独立清理本机连接，不等待服务器，不发送远程 detach / quit。被删除的记录不再自动恢复；远程仍存在时，可稍后重新扫描添加。
- 终端连接不做无限自动重试。只有你点“重新连接”才尝试；附加过程中为处理瞬时 socket 转换最多重试 3 次，远程会话已不存在时停止。下载断线重试与终端会话管理相互独立。
- 窗口 ×：逐窗口选择 **Detach / 分离** 或 **Close / 结束**。
- **关闭服务器**：逐个列出该服务器的 terminal，每一个都可分别选 Detach 或 Close，默认 Detach；同时暂停该服务器的下载，清理本程序为其建立的 SSH 主连接和转发。
- Detach 保留远程任务及布局。重新切回该服务器、刷新页面或重新启动程序后，会默认打开保留的窗口，**只恢复布局，不自动发起终端连接**；点对应窗口“重新连接”才恢复。
- Close 发送 `screen -X quit`，终止该 screen 内全部程序。**已 Close 的会话不再显示。** 若远程结束操作失败，会保留记录并报告错误，不假装已结束。
- 切换服务器不关闭连接。掉线、关浏览器、刷新、退出程序都不发送 quit；每个受管理 screen 都开启 autodetach。
- 手动执行 exit、管理员结束任务或服务器自身重启仍可结束会话。GNU screen 不支持进程跨服务器重启保活。

终端尚未完成登录时无法确认远程 screen 是否已建立，Close 会禁用；可以 Detach 先断开本机。

## 转发

**每个窗口独立设置端口转发**。新建窗口时必须选择，标题栏的“转发:开 / 关”可随时查看和修改。已连接窗口更改设置时，会只分离并重连这个窗口，不结束 screen；其他窗口保持各自选择。

恢复窗口会保留上次设置，点“重新连接”按标题栏显示的设置连接。文件浏览与下载使用所选服务器最近一次批准的转发方式；自动重试沿用该下载任务的设置。

- 启用：沿用配置中的 LocalForward、RemoteForward、DynamicForward 及配置的 agent / X11 选项。转发建立失败会显示连接错误。
- 不启用：关闭本次 SSH 的 LocalForward、RemoteForward、DynamicForward；ProxyJump / ProxyCommand、agent、X11 等其他配置仍由系统 SSH 解析。
- 下载掉线自动重试沿用批准的选择，不反复弹窗。
- 不修改 SSH config。程序使用自己的 ControlMaster / ControlPath、禁用 LocalCommand、覆盖 RemoteCommand。不同服务器的连接相互独立。
- 同一服务器的“启用”和“不启用”使用两个不同的 SSH 主连接。启用转发的多个窗口复用一个主连接，避免争抢相同监听端口；已建立的转发可能继续被同组窗口使用。关闭整个服务器时一并清理两组主连接。
- 原生 Windows 使用一个独立的共享 SSH 转发连接承载该服务器已有配置中的转发，窗口关闭 / 分离后保留，关闭服务器或退出程序时释放。窗口的启用 / 不启用选择和 SSH config 均沿用原有设置，不重复占用端口。Windows OpenSSH 不支持 ControlMaster，文件与会话管理使用独立连接；需要密码 / MFA 时可在界面的认证框完成，不复用其他终端输入过的密码。
- 本程序关闭服务器不会操作其他软件已经建立的 SSH / 转发。

## 当前层文件与大目录

左侧 **文件列表** 按钮打开一个独立、全高的文件面板；点“折叠”收起。拖动文件面板右侧边缘调整宽度，宽度和展开状态保存在本机。

选择服务器，输入路径点 →；留空读取远程主目录。↑ 返回父目录，↻ 从头刷新。

- 只读取**当前这一层**，不递归遍历、不预先建树、不把目录列表写入磁盘。
- 每页最多 200 项，点下一页继续，替换当前页显示，避免一次渲染数万项。
- 按后缀分组、可折叠；超过 15 项的文件组默认折叠。数量与排序仅针对当前页，不为统计后缀扫描全目录。
- 分页只保留短暂的在线目录句柄，空闲 2 分钟释放。掉线 / 失效后刷新当前目录。
- 文件行 ↓ 开始下载。仅支持普通文件，不递归打包目录。非 UTF-8 文件名会限制操作，避免地址错误。

如果服务器要求密码 / 私钥口令 / MFA，文件操作会直接弹出 SSH 认证框，完成后继续读取或下载。

## 下载、暂停和断点续传

结果保存在程序文件夹的 **downloads/**。点“下载任务”管理当前服务器的下载；“在本机显示”定位文件。切换工作区不会暂停后台服务器的下载。

- 下载中写入 `.part`，每完成 1 MiB 刷写磁盘并保存断点，完成后才更名为最终文件。自动加唯一后缀，避免同名覆盖。
- 支持暂停、继续、取消；取消也保留部分文件。
- 连接中断后自动重试并从已确认断点续传，等待 2、4、8 秒逐渐增加，上限 60 秒。
- 退出程序保存断点，再次启动后点“继续”。**保留 data/ 与 downloads/，不要只复制 app.py。**
- 恢复时核对大小、修改时间、开头 64 KiB 的 SHA-256，以及最后一个断点块的远程 / 本地 SHA-256。崩溃留下的未确认尾部最多重取 1 MiB。
- 文件变化或断点损坏会停止续传并保留部分文件；“保留旧文件并重新下载”会备份旧 `.part` 后重下。
- SSH 复用连接失效而服务器要求密码 / MFA 时，自动重试会请求本次认证，不代填已输入的密码。取消或认证失败则暂停下载，保留部分文件和断点；点击“继续”可重新认证。

这些检查处理断网恢复和常见文件变化，不提供远程文件快照。若文件被原位修改，同时刻意保持大小 / 时间戳且避开校验位置，不能保证检测。需要严格内容一致性时，应下载已完成写入的文件并核对服务器提供的整文件校验和。

## 本机数据与限制

`data/workspace.json` 保存服务器条目、screen 标识和布局；`data/downloads.json` 保存下载断点。下载结果、部分文件及备份在 `downloads/`。

不保存 SSH 密码、密钥口令、私钥内容或终端输出。程序仅监听 127.0.0.1，API / WebSocket 使用启动令牌与来源检查。

最多同时打开 32 个终端、保留 64 个未结束会话和 32 个未完成下载。终端保留最多 20,000 行本地滚动历史。暂不支持远程图形桌面应用。

## iPhone / iPad 免安装访问

电脑保持开机、联网、不睡眠，并运行 ScreenDesk。手机使用 Safari，不需要安装 SSH 客户端，也不需要电脑和手机处于同一个 Wi‑Fi。

1. 电脑端右上角点 **手机访问**。此功能默认关闭，不会随启动自动开放外网。
2. 电脑需要安装官方 `cloudflared`：macOS 使用 `brew install cloudflared`；Windows 使用 `winget install --id Cloudflare.cloudflared`。手机不需要安装它。
3. 阅读弹窗中的转发说明，点 **开启外网访问**，等状态变为可访问后复制完整链接，发到自己的手机。
4. 手机用 Safari 打开链接。窄屏一次显示一个终端，上方下拉切换窗口，左上角打开服务器和会话侧栏。点底部 **键盘** 开始输入，再点 **收起键盘** 回到浏览状态。底部也有 Esc、Tab、Ctrl+C / D / A 和方向键。
5. 添加到主屏幕后若提示密钥，粘贴电脑显示的完整链接即可。可明确勾选“记住此设备”；默认只保留当前浏览器会话，不保存 SSH 密码。

SSH 仍使用电脑上的配置和密钥，端口转发也发生在电脑上。切换终端不会关闭其他连接。手机切后台、锁屏或断网可能导致浏览器连接中断；远程 screen 不结束，回来后点“重新连接”。手机显示方式不覆盖桌面窗口的位置和大小。

### 电脑和手机同时看同一个终端

两端打开同一会话后会同步显示，后台共用一条 SSH / screen 连接。先打开的一端获得操作权，后来打开的默认只读。窗口底部显示“操作中”或“只读”，以及观看端数量。点 **接管操作** 可立即获得输入权，原操作端变为只读；切换不重连 SSH、不分离 screen。点 **交出操作** 后所有端暂时只读，直到有人再次接管。

同一后台上的两个桌面页面也使用这套操作权规则。分别运行后台的两台电脑各自建立 SSH，已连接的 screen 需要先在原端分离才能换一台电脑连接。

服务器只接受当前操作端的按键、粘贴、鼠标输入和行列数调整，其他端发送这些数据也会被拒绝。操作端掉线后，其他端继续观看并变为只读，需要明确接管后才能输入。只读端可选择复制、调整本地字号、滚动画面，点“回看”查看本地文字历史。操作端决定终端的行列数，只读端按相同尺寸显示，可横向或纵向滚动查看，避免两端尺寸不同导致错位。

关闭 / 分离一个页面不影响其他观看端；最后一个页面断开时才分离远程终端。明确结束 screen 会结束任务并通知所有观看端，连接中的只读页面须先接管才能执行。关闭手机入口只移除手机观看端，电脑端继续使用；关闭整个服务器或退出后台仍会断开它的全部连接并保留远程任务。共享观看期间沿用当前终端的端口转发配置；要更改转发，先关闭其他观看页面，再由操作端修改。

后来加入的页面通过有序回放恢复当前画面，较长输出会保存内存中的画面快照及最近 1,000 行历史，再接上后续输出。不会使用旧版 screen 的有损 hardcopy，也不会把终端内容写入磁盘。每个终端最多 8 个观看页面；输出缓慢的观看端会单独分离，不阻塞其他端或远程任务。

文件区仍只按需读取当前层，每页最多 200 项，可按后缀折叠。远程文件首先下载到后台电脑，掉线重试和断点保存由电脑负责；完成后手机端显示 **保存到手机**，由 Safari 下载。文件接口支持 HTTP Range；手机保存中断后能否自动续传取决于 Safari，也可以回到任务列表重新保存。浏览器关闭不影响电脑继续下载远程文件。

外网入口使用 [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)，不需要域名或 Cloudflare 账号，终端输入输出与文件流量经过 Cloudflare 的 HTTPS 网关。临时网址每次开启会改变，服务不保证持续可用；固定网址和长期使用可配置正式 Tunnel。网络中断时 cloudflared 会重连，入口进程退出时手机密钥会撤销，需重新开启并使用新链接。

完整手机链接带有独立的随机访问密钥，拥有它即可操作工作台，请只保存在自己的设备上。密钥保存在进程内存中，不写入配置或 Git；手机明确选择“记住此设备”时才会保存在该浏览器本地。电脑上点 **关闭手机访问** 会立即撤销旧密钥、断开手机连接并保留远程任务，电脑本地的其他终端继续工作。退出程序也会关闭入口。手机不能关闭整个电脑后台或管理外网入口。

程序始终只监听 `127.0.0.1`，不开放路由器端口。手机请求仍校验密钥与来源，WebSocket 使用 WSS；未知来源、过期密钥及手机端管理入口的请求会被拒绝。手机文件下载使用仅限下载路径的 HttpOnly / Secure / SameSite Cookie，其余 API 和终端仍要求显式访问密钥。默认不会自动启用任何第三方网络服务。

## 终端滚动和日夜模式

- 在终端窗口内使用鼠标滚轮 / 触控板上下滚动；`Shift+PageUp / PageDown` 翻页，`Shift+Home` 到顶部，`Shift+End` 或窗口底部“回到底部”返回实时输出。滚轮事件留在这个窗口，不带动整个工作台。
- 本地滚动直接回看终端已收到的输出，保留中文、框线和颜色。screen 的外层显示留在本地普通缓冲区，远程全屏界面由 screen 管理。本地回看不会发送远程输入。
- Codex 等程序把旧回复从顶部滚走或清屏重画时，已显示的内容会进入本地滚动历史。只读窗口也可以直接上滚，新的输出不会打断回看。远程程序明确清空滚动缓冲时，已收到的记录仍可在「回看」查看。拖动窗口边缘时，松开后才更新远程终端尺寸，减少输出期间的重复重绘。
- 点底部“回看”打开可选择、复制的本地文字快照，点“返回终端”或按 Esc 回去。同一窗口掉线后重新连接，之前收到的内容仍可在这里查看；关闭窗口、刷新网页或退出程序后清除。本地快照最多保留最近 20,000 行 / 2,097,152 个 UTF-16 单元，不落盘。
- 服务器上重新连接前的更早历史，可在终端按 `Ctrl+A`，再按 `[` 进入 screen 原生回看，用方向键 / PageUp 翻页，按 Esc 返回。旧版 screen 的 `hardcopy` 会破坏中文等字符，程序已移除这条导出路径。screen 没有保留下来的旧输出无法补回。
- nvitop、Codex 全屏模式等交互程序启用鼠标时，由 xterm 原生处理滚轮、点击和移动，事件按程序协商的协议发送。按住 Shift 滚动查看本地历史，Shift+拖动可以本地选择文字。只读观看端只滚动本地记录。
- 右上角主题可选“跟随系统 / 日间模式 / 夜间模式”。日间终端默认白底深字，夜间黑底浅字；默认跟随系统外观，选择保存在本机浏览器。所有已打开终端立即换色，不重连 SSH。历史区域与窗口边框也一起切换。

## 鼠标坐标与 Codex 等终端界面

终端根据远程程序启用的鼠标模式工作。普通 shell 收到键盘输入，滚轮回看本地历史；交互程序启用鼠标后，xterm 负责生成相应的鼠标事件。文字输入保留 UTF-8，旧版鼠标协议使用独立的字节输入通道，避免坐标被截短或重新编码。无需切换鼠标开关。

连接时还会清除 screen 默认的 `Km` 前缀改写：后台创建的 screen 在部分现代 terminfo 配置下会把 SGR 鼠标前缀改成旧版格式，使坐标数字落入应用的输入栏。这里只去掉这条默认按键改写，鼠标模式仍由应用协商。已有会话重新附加时也会应用修正。

Windows 的 ConPTY 输入接口使用 Unicode。SGR 鼠标事件通过文本通道正常传递；旧版 X10 鼠标事件的坐标字节若超出 ASCII 范围，程序会给出提示并保留键盘连接。Mac 和 Linux 的 PTY 可原样传递这些字节。

## screen / socket 卡住的处理

只有主动点击“扫描服务器 screen”才读取当前账号的完整 `screen -ls`；创建、恢复、核对、诊断仍只匹配当前窗口的标识。每次远程查询 / 控制最多等待 6 秒，附加无输出最多等待 15 秒；socket 状态刚转换时最多重试附加 3 次，不新建替代会话。

本版本启用 screen 的 `autodetach on`、`defnonblock 1` 并关闭显示流控。浏览器输出使用有界队列和处理确认，慢显示端不会让本机无限缓冲；持续停收会分离本机连接，保留远程任务。SSH 密码 / MFA 短提示会立即显示。

窗口标题栏 **诊断** 只查询当前 screen 版本、目标会话和目标 PID 状态，并有超时。它不删除 socket，不发送 kill 或 quit。诊断结果可以帮助区分 SSH 不通、目标 screen 已结束和 socket 控制超时。

已存在的坏 socket 不会被程序自动清除。未取得服务器实际诊断结果时，不能断言某次卡死的唯一根因；不要删除活跃会话的 socket 来试错。

## 测试

macOS / Linux 本机隔离测试，不访问真实服务器：

```sh
SCREENDESK_TEST_SCREEN=1 PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

需要 screen 和本地 SFTP server；macOS 使用自带 `/usr/libexec/sftp-server`，Ubuntu 可安装 `openssh-sftp-server`。覆盖 SFTP 中断续传、暂停 / 重启恢复、源文件变化、大目录分页、screen 与 WebSocket 断线保留、服务器切换、逐终端关闭选择、布局恢复、SSH config、Git 更新保护和 WSL 桌面入口。新增隔离 screen 的双工作区扫描 / 名称还原、忽略恢复、添加去重与本机删除不等待卡住终端的测试；CI 包括 Windows、macOS 和 Ubuntu。

认证集成测试先安装 `python3 -m pip install -r requirements-test.txt`。测试使用真实系统 OpenSSH 与临时回环 SSH/SFTP 服务，验证无公钥的密码 + MFA、文件二进制传输、取消、错误密码和主机指纹变更拒绝；Paramiko 仅用于测试服务器，不是程序运行依赖。

另可运行 `node tests/test_mouse.mjs` 验证鼠标模式过滤，包括跨数据块的控制序列、混合终端模式和远程鼠标主动开启。Node 仅用于这项开发测试，日常运行不需要它。

`node tests/test_terminal_input.mjs` 使用捆绑的 xterm 原生编码器验证文字、方向键、Shift+方向键、点击和滚轮。启用上述 screen 集成测试时，还会通过正式连接脚本将这些输入送入隔离 screen 内的真实 curses 编辑器，逐字节核对应用收到的数据，并检查滚动、点击不会污染输入到一半的中文草稿；不连接真实 SSH 服务器。
