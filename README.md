# ScreenDesk

代码仓库：[Yankersey/SHHConnector](https://github.com/Yankersey/SHHConnector)。[Windows / WSL 安装](WINDOWS.md) · [修改与双机同步](CONTRIBUTING.md)。

本地 SSH / GNU screen 工作台，支持 macOS / Linux，Python 3.9+。无需 pip、npm 安装，终端资源已打包。

## 启动

macOS 解压整个文件夹后，双击 **启动 ScreenDesk.command**。浏览器会自动打开。也可在程序目录运行：

```sh
sh start.sh
```

Linux 运行 `sh start.sh`。Windows 安装 WSL / Ubuntu 后运行同一命令，或双击 `start-windows.cmd`，详见 [Windows 使用说明](WINDOWS.md)。暂不支持原生 Windows Python。服务器需要 SSH、SFTP 和 GNU screen，不需要远程 Python。

Git 克隆版本会在启动器启动前检查远程分支并执行快进更新；界面左下角显示提交号。离线 / 开发时显式使用 `sh start.sh --offline`。直接运行 `python3 app.py` 可以启动本地代码，但不会检查 Git 更新。ZIP 版本不包含 .git，因此没有自动更新功能。

两台电脑应分别克隆同一个仓库；修改后提交并推送，另一台退出旧程序并重新启动即可拉取。SSH 配置、密钥、布局、断点与下载数据均保留在各自电脑，不上传仓库。

再次双击启动器会打开已有程序。退出请点右上角“退出程序”，或在启动的终端按 Ctrl+C。

## 服务器与工作区

- 左侧直接读取 **~/.ssh/config** 的具体 Host 别名，支持 Include。点击 ↻ 重新读取，不需要手工录入服务器。
- `Host *`、带通配符和否定的规则不单独列为机器；连接时仍由系统 SSH 完整解析配置，包括端口、用户名、私钥、跳板机及匹配规则。
- 点击服务器会切换**整个终端工作区**。其他服务器的 SSH、终端和下载继续保持，切换本身不分离会话。
- 顶部仅保留连接信息和操作按钮，让终端获得更多空间。
- 如需使用其他 config：`python3 app.py --ssh-config /你的路径/config`。

Include 只静态读取 Host 别名，不执行 Match exec。放在复杂条件 Include 里的别名可能也会显示；最终连接行为以系统 SSH 对该别名的解析为准。

## 新建与恢复终端

1. 选择服务器，点“新建窗口”。**必须命名**，支持中文。
2. 每个新窗口都要明确选择是否启用 SSH 配置中的端口转发；不同窗口可以选择不同方式。
3. 密码、密钥口令、二次认证、首次指纹确认，均在终端内按系统 SSH 提示处理。
4. 每个窗口对应一个独立 GNU screen，可运行 bash、Python、vim、htop 等终端程序。

拖动标题栏移动，拖动八个方向的边缘 / 角落调整大小；双击标题栏或点 □ 最大化 / 还原。A− / A＋ 调字号。平铺、层叠仅整理当前服务器的窗口。布局自动保存。

中文名称用于本地窗口；远程 screen 使用安全名称与唯一后缀，标识显示在窗口右下角。服务器上可通过 `screen -ls` 查询。

新建对话框中可填写已有 `PID.name`，接管已有 screen（会分离它原有的终端）。

## 关闭与保留

- **核对会话**：只核对当前服务器在本机记录的 screen。确认远程已不存在时，移出工作区并停止该窗口的连接；SSH 掉线、超时、权限问题和坏 socket 都显示“无法确认”，保留记录。
- 左侧每条会话都有 **移除记录**，核对窗口也提供 **移除本机记录**。即使当前连接中也可移除：只分离本机连接并清理记录，不结束云端 screen。被移除的记录以后不再恢复或重连。
- 终端连接不做无限自动重试。只有你点“重新连接”才尝试；附加过程中为处理瞬时 socket 转换最多重试 3 次，远程会话已不存在时停止。下载断线重试与终端会话管理相互独立。
- 窗口 ×：逐窗口选择 **Detach / 分离** 或 **Close / 结束**。
- **关闭服务器**：逐个列出该服务器的 terminal，每一个都可分别选 Detach 或 Close，默认 Detach；同时暂停该服务器的下载，清理本程序为其建立的 SSH 主连接和转发。
- Detach 保留远程任务及布局。重新切回该服务器、刷新页面或重新启动程序后，会默认打开保留的窗口，**只恢复布局，不自动发起终端连接**；点对应窗口“重新连接”才恢复。
- Close 发送 `screen -X quit`，终止该 screen 内全部程序。**已 Close 的会话不再显示。** 若远程结束操作失败，会保留记录并报告错误，不假装已结束。
- 切换服务器不关闭连接。掉线、关浏览器、刷新、退出程序都不发送 quit；每个受管理 screen 都开启 autodetach。
- 手动执行 exit、管理员结束任务或服务器自身重启仍可结束会话。GNU screen 不支持进程跨服务器重启保活。

终端尚未完成登录时无法确认远程 screen 是否已建立，Close 会禁用；可以 Detach 先断开本机。

## 转发

**每个窗口独立设置端口转发**。新建窗口时必须选择，标题栏的“转发:开 / 关”可随时查看和修改。已连接窗口更改设置时，会只分离并重连这个窗口，不结束 screen；其他窗口保持各自选择。

恢复窗口会保留上次设置，点“重新连接”按标题栏显示的设置连接。文件浏览与下载使用所选服务器最近一次批准的转发方式；自动重试沿用该下载任务的设置。

- 启用：沿用配置中的 LocalForward、RemoteForward、DynamicForward 及配置的 agent / X11 选项。转发建立失败会显示连接错误。
- 不启用：关闭本次 SSH 的 LocalForward、RemoteForward、DynamicForward；ProxyJump / ProxyCommand、agent、X11 等其他配置仍由系统 SSH 解析。
- 下载掉线自动重试沿用批准的选择，不反复弹窗。
- 不修改 SSH config。程序使用自己的 ControlMaster / ControlPath、禁用 LocalCommand、覆盖 RemoteCommand。不同服务器的连接相互独立。
- 同一服务器的“启用”和“不启用”使用两个不同的 SSH 主连接。启用转发的多个窗口复用一个主连接，避免争抢相同监听端口；已建立的转发可能继续被同组窗口使用。关闭整个服务器时一并清理两组主连接。
- 本程序关闭服务器不会操作其他软件已经建立的 SSH / 转发。

## 当前层文件与大目录

左侧 **文件列表** 按钮打开一个独立、全高的文件面板；点“折叠”收起。拖动文件面板右侧边缘调整宽度，宽度和展开状态保存在本机。

选择服务器，输入路径点 →；留空读取远程主目录。↑ 返回父目录，↻ 从头刷新。

- 只读取**当前这一层**，不递归遍历、不预先建树、不把目录列表写入磁盘。
- 每页最多 200 项，点下一页继续，替换当前页显示，避免一次渲染数万项。
- 按后缀分组、可折叠；超过 15 项的文件组默认折叠。数量与排序仅针对当前页，不为统计后缀扫描全目录。
- 分页只保留短暂的在线目录句柄，空闲 2 分钟释放。掉线 / 失效后刷新当前目录。
- 文件行 ↓ 开始下载。仅支持普通文件，不递归打包目录。非 UTF-8 文件名会限制操作，避免地址错误。

如果服务器要求交互式密码 / MFA，请先打开该服务器的终端完成登录，再浏览或下载文件。

## 下载、暂停和断点续传

结果保存在程序文件夹的 **downloads/**。点“下载任务”管理当前服务器的下载；“在本机显示”定位文件。切换工作区不会暂停后台服务器的下载。

- 下载中写入 `.part`，每完成 1 MiB 刷写磁盘并保存断点，完成后才更名为最终文件。自动加唯一后缀，避免同名覆盖。
- 支持暂停、继续、取消；取消也保留部分文件。
- 连接中断后自动重试并从已确认断点续传，等待 2、4、8 秒逐渐增加，上限 60 秒。
- 退出程序保存断点，再次启动后点“继续”。**保留 data/ 与 downloads/，不要只复制 app.py。**
- 恢复时核对大小、修改时间、开头 64 KiB 的 SHA-256，以及最后一个断点块的远程 / 本地 SHA-256。崩溃留下的未确认尾部最多重取 1 MiB。
- 文件变化或断点损坏会停止续传并保留部分文件；“保留旧文件并重新下载”会备份旧 `.part` 后重下。
- SSH 复用连接失效而服务器要求密码 / MFA 时，程序不会代填密码。先重新连接该服务器终端完成认证，下载会在后续重试继续。

这些检查处理断网恢复和常见文件变化，不提供远程文件快照。若文件被原位修改，同时刻意保持大小 / 时间戳且避开校验位置，不能保证检测。需要严格内容一致性时，应下载已完成写入的文件并核对服务器提供的整文件校验和。

## 本机数据与限制

`data/workspace.json` 保存服务器条目、screen 标识和布局；`data/downloads.json` 保存下载断点。下载结果、部分文件及备份在 `downloads/`。

不保存 SSH 密码、密钥口令、私钥内容或终端输出。程序仅监听 127.0.0.1，API / WebSocket 使用启动令牌与来源检查。

最多同时打开 32 个终端、保留 64 个未结束会话和 32 个未完成下载。终端滚动历史为本次连接的 5,000 行。暂不支持远程图形桌面应用。

## 鼠标坐标与 Codex 等终端界面

默认每个窗口为 **鼠标:本地**：拦截远程程序开启的鼠标上报模式，并拦截 SGR / X10 鼠标坐标输入，防止移动 / 点击鼠标时坐标串进入远程 Codex 或 shell。普通选择、复制和滚动留在本机。重新连接会重置旧终端状态。

确实需要远程程序接收鼠标操作时，点击该窗口的“鼠标:本地”切换为“鼠标:远程”。这是每个窗口独立的设置，远程鼠标模式下程序可以接收点击、滚动和移动事件。

## screen / socket 卡住的处理

程序不会调用全局 `screen -ls` 扫描其他会话；创建、恢复、诊断只匹配当前窗口的标识。每次远程查询 / 控制最多等待 6 秒，附加无输出最多等待 15 秒；socket 状态刚转换时最多重试附加 3 次，不新建替代会话。

本版本启用 screen 的 `autodetach on`、`defnonblock 1` 并关闭显示流控。浏览器输出使用有界队列和处理确认，慢显示端不会让本机无限缓冲；持续停收会分离本机连接，保留远程任务。SSH 密码 / MFA 短提示会立即显示。

窗口标题栏 **诊断** 只查询当前 screen 版本、目标会话和目标 PID 状态，并有超时。它不删除 socket，不发送 kill 或 quit。诊断结果可以帮助区分 SSH 不通、目标 screen 已结束和 socket 控制超时。

已存在的坏 socket 不会被程序自动清除。未取得服务器实际诊断结果时，不能断言某次卡死的唯一根因；不要删除活跃会话的 socket 来试错。

## 测试

macOS / Linux 本机隔离测试，不访问真实服务器：

```sh
SCREENDESK_TEST_SCREEN=1 PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

需要 screen 和本地 SFTP server；macOS 使用自带 `/usr/libexec/sftp-server`，Ubuntu 可安装 `openssh-sftp-server`。覆盖 SFTP 中断续传、暂停 / 重启恢复、源文件变化、大目录分页、screen 与 WebSocket 断线保留、服务器切换、逐终端关闭选择、布局恢复、SSH config、Git 更新保护和 WSL 桌面入口。

另可运行 `node tests/test_mouse.mjs` 验证鼠标模式过滤，包括跨数据块的控制序列、混合终端模式和远程鼠标主动开启。Node 仅用于这项开发测试，日常运行不需要它。
